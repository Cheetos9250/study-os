# Audit, 17 Nov 2026 (TASKS.md task 12)

Measured with Playwright (Chromium) at 820×1180 (iPad portrait), with fonts and Workers blocked, on a local server.

## 1. Load time on iPad
- Page `load` event on a local server: Today 130 ms, Accounting practice 154 ms, Economics practice 151 ms, other core pages 15–95 ms.
- `acc.html` is the largest page at 600 KB, because the course data is embedded as `const D={...}`. eco is 142 KB, zh 148 KB, math 77 KB and eng 66 KB. Since `sw.js` (#149), repeat visits and offline opens use the cached copy.
- Redrawing practice (`renderQ`, which also redraws all 698 question-number buttons in Accounting) takes about 2.5 ms per tap on desktop Chromium. That is fine even on a slower iPad. No change needed.
- Possible later work: move `D` for acc into `data/acc.json` so the page shell parses faster. This changes a large file, so it is not done here.

## 2. Accessibility (fixed in this PR)
- Every visible button and link on the core pages is at least 40×40 px, and most are 44 px. The one smaller control was the Today subject-card image button (44×36). It is now 44×44.
- Unlabeled form controls: only two, both on `accounting-textbook.html`. They are the answer box (`#answer`) and the hidden file input for the answers backup. Both now have accessible names.
- Contrast and focus: core pages use ink on paper (≥ 15:1) and visible 3 px focus outlines. Course pages use `assets/study-unify.css` tokens. No problems found.

## 3. Duplicate code
- `acc.html`, `eco.html` and `math.html` carry nearly the same 600-line script: the quiz engine, cards, the sync engine and deep links. Any fix has to be made three times; the Q1-jump fix in #153 is an example.
- Recommended next step: move the shared engine into `scripts/study-course-engine.js`, keeping storage keys and formats identical, in its own PR with the existing browser tests.
- The course pages keep their own sync engine (`window.__xs`) next to `scripts/study-cloud.js`. Both use compare-and-set and the same merge rules for course data. Merging them is part of the same refactor.

## 4. Tests
- `node --test tests/*.test.cjs vocabloom/tests/*.test.cjs` takes about 2 s for ~400 tests.
- The slow ones are the Playwright jobs in CI (1–4 minutes each, mostly browser install). They are already split by workflow and filtered by path, so an unrelated change does not run them.
